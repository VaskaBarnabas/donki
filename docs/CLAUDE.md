# Legacy CRM – szakdolgozati prototípus

A teljes felépítést a @docs/LEGACY_CRM_BUILD_SPEC.md írja le. Ezt kövesd, fázisonként haladva.

## Munkamód
- Egyszerre mindig csak egy fázison dolgozz. A fázis végén futtasd a füsttesztet, foglald össze, mit csináltál, és állj meg.
- Mielőtt egy fázisba kezdesz, írj tervet, és várd meg a jóváhagyásomat.
- Ha a spec valamiben nem egyértelmű vagy ellentmondásos, kérdezz, ne találgass.
- Az Állapot részt midnig frissítsd, hogy nyomon tudjuk követni éppen hol áll a folyamat

## Környezet
- Supabase felhőprojekt, már linkelve. Migrációk: `npx supabase db push` (nem `db reset`).
- A Supabase-ben csak a felhasználók vannak (Auth + `profiles`). Dashboard-beállítást én végzek; szólj, amikor erre szükség van.
- A rendszerek konténerben futnak (Docker Desktop); a belső titkokat az `npm run stack:secrets` generálja a `.env.stack`-be.
- A `.env.local`-t én töltöm ki; te a `.env.example`-t tartsd karban.
- A README változtatási napló: fázisonként mit változtattunk és miért. Futtatási parancsok, curl-példák ne kerüljenek bele (azok itt vannak).

## Parancsok
- **Rendszer (15. fázis óta minden konténerben):** egyszer `npm run stack:secrets` (belső titkok → `.env.stack`, gitignored; meglévőt nem ír felül), majd `npm run stack:up` (build + indítás, ~29 konténer, ~1,7 GB) / `stack:down` / `stack:logs` / `stack:reset` (kötetek törlése → seed állapot). Kézi compose: `npm run dc -- <parancs>` (pl. `npm run dc -- ps`, `npm run dc -- logs -f orders`, `npm run dc -- up -d --build billing`). Stripe webhook-továbbító: `npm run dc -- --profile stripe up -d stripe-cli`. A sima `docker compose` env-fájlok nélkül figyelmeztet és üres titkokkal dolgozna – mindig a `dc` scriptet használd.
- **Címek a gépről:** portál `:3000`; CRM PostgREST `:4100`; quote `:4101`; orders `:4102`; billing `:4103`; payments `:4104`; support `:4105`; inventory worker health `:4106`; MCP `:3201–3205`; Flowable `:8080`; belső PostgREST-ek (tesztekhez): `:54101–54107` (raktár API: `:54106`, mcp: `:54107`); docker-proxy `:2375`. Mind `127.0.0.1`-en. Minden rendszer: `GET /health`.
- **Rendszer adatbázisa:** `npm run dc -- exec <rendszer>-db psql -U postgres` (a rendszerek: crm, quote, orders, inventory, billing, payments, support, mcp); a Flowable: `-d flowable` az `orders-db`-n. Init: `systems/<rendszer>/db/` (csak első induláskor fut; módosítás után `stack:reset` vagy a kötet törlése).
- **Supabase (csak felhasználók):** migráció: `npx supabase db push -p "$SUPABASE_DB_PASSWORD"`; SQL: `npx supabase db query --linked "<sql>"`. A régi modulsémák még ott vannak (törlés: jóváhagyásra vár); a régi `supabase/seed.sql` már nem használt.
- Flowable: `npm run flowable:logs`; BPMN kézi telepítése: `npm run flowable:deploy` (a rendeléskezelő induláskor magától telepíti); REST: `http://localhost:8080/flowable-rest/service` Basic auth-tal.
- Lint: `npx eslint app components lib legacy systems mcp scripts`
- Portál natívan (hot reload): `npm run dev` (a rendszerek konténerben; a `next.config` a `.env.stack`-et is betölti)
- Füsttesztek (mind a konténeres rendszeren; közös segéd: `scripts/smoke/rendszerek.ts`): `01-alapok` (rendszerenkénti adatbázisok), `02-crm-katalogus`, `03-raktar` (~2 perc, DLQ), `04-ajanlat`, `05-szamlazas`, `06-flowable`, `07-rendelesek` (~3-4 perc), `08-fizetes` (stripe profil, ~1,5 perc), `09-support`, `11-order-to-cash` (stripe + SzámlaBridge, ~90 mp), `15-rendszerek` (egészség, függetlenség, kiesés-szimuláció; rendszereket állít le és indít vissza – ne fusson más teszttel párhuzamosan). Futtatás: `npx tsx scripts/smoke/<név>.ts`. A tesztek a kiszállított készletet visszavételezik (KORREKCIO).
- MCP: konténerben futnak (`mcp-orders` … `mcp-support`, 3201–3205); natívan: `npm run mcp:<szerver>` / `npx tsx mcp/servers/<szerver>/index.ts --stdio` (stdio-n ne `npm run`); a tokenek: `MCP_TOKENS` (.env.local) vagy a generált demo-tokenek (.env.stack). Inspector: `npx @modelcontextprotocol/inspector`. MCP szerverben naplózni csak stderr-re szabad (`log()`).
- MCP füsttesztek (saját natív szerverpéldány külön porton, ideiglenes tokenekkel, a konténeres rendszerek ellen; segéd: `scripts/smoke/mcp-segedek.ts`): `13-mcp-orders` (port 3291), `14-mcp-sales` (3292), `14-mcp-inventory` (3293), `14-mcp-finance` (3294), `14-mcp-support` (3295; kell egy kiszállított TK-00001-es rendelés), `14-mcp-order-to-cash` (3281–3285, stripe profil + SzámlaBridge).
- curl (CRM/katalógus): `http://localhost:4100/<tábla>`, `Authorization: Bearer $CRM_API_KEY`, `Accept-Profile: crm|catalog` olvasáshoz, `Content-Profile` íráshoz és RPC-hez; pl. `POST /rpc/price_for` `{"product_code":"TK-00008","customer_group":"KIEMELT"}`
