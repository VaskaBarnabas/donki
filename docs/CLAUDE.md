# Legacy CRM – szakdolgozati prototípus

A teljes felépítést a @docs/LEGACY_CRM_BUILD_SPEC.md írja le. Ezt kövesd, fázisonként haladva.

## Munkamód
- Egyszerre mindig csak egy fázison dolgozz. A fázis végén futtasd a füsttesztet, foglald össze, mit csináltál, és állj meg.
- Mielőtt egy fázisba kezdesz, írj tervet, és várd meg a jóváhagyásomat.
- Ha a spec valamiben nem egyértelmű vagy ellentmondásos, kérdezz, ne találgass.
- Az Állapot részt midnig frissítsd, hogy nyomon tudjuk követni éppen hol áll a folyamat

## Környezet
- Supabase felhőprojekt, már linkelve. Migrációk: `npx supabase db push` (nem `db reset`).
- A Supabase-ben csak a felhasználók vannak (Auth + `profiles`). Dashboard-beállítást én végzek; szólj, amikor erre szükség van.
- A rendszerek konténerben futnak (Docker Desktop); a belső titkokat az `npm run stack:secrets` generálja a `.env.stack`-be.
- A `.env.local`-t én töltöm ki; te a `.env.example`-t tartsd karban.
- A README változtatási napló: fázisonként mit változtattunk és miért. Futtatási parancsok, curl-példák ne kerüljenek bele (azok itt vannak).

## Parancsok
- **Rendszer (15. fázis óta minden konténerben):** egyszer `npm run stack:secrets` (belső titkok → `.env.stack`, gitignored; meglévőt nem ír felül), majd `npm run stack:up` (build + indítás, ~28 konténer a portál nélkül, ~1,6 GB) / `stack:down` / `stack:logs` / `stack:reset` (kötetek törlése → seed állapot). Kézi compose: `npm run dc -- <parancs>` (pl. `npm run dc -- ps`, `npm run dc -- logs -f orders`, `npm run dc -- up -d --build billing`). Stripe webhook-továbbító: `npm run dc -- --profile stripe up -d stripe-cli`. A sima `docker compose` env-fájlok nélkül figyelmeztet és üres titkokkal dolgozna – mindig a `dc` scriptet használd.
- **Címek a gépről:** portál `:3000`; CRM PostgREST `:4100`; quote `:4101`; orders `:4102`; billing `:4103`; payments `:4104`; support `:4105`; inventory worker health `:4106`; MCP `:3201–3205`; Flowable `:8080`; belső PostgREST-ek (tesztekhez): `:54101–54107` (raktár API: `:54106`, mcp: `:54107`); docker-proxy `:2375`. Mind `127.0.0.1`-en. Minden rendszer: `GET /health`.
- **Rendszer adatbázisa:** `npm run dc -- exec <rendszer>-db psql -U postgres` (a rendszerek: crm, quote, orders, inventory, billing, payments, support, mcp); a Flowable: `-d flowable` az `orders-db`-n. Init: `systems/<rendszer>/db/` (csak első induláskor fut; módosítás után `stack:reset` vagy a kötet törlése).
- **Supabase (csak felhasználók):** migráció: `npx supabase db push -p "$SUPABASE_DB_PASSWORD"`; SQL: `npx supabase db query --linked "<sql>"`. A régi modulsémák, cron jobok és üzenetsorok 2026-11-02-án törölve (`20261102100000_regi_modulsemak_torlese.sql`; mentés: `../supabase-mentes-2026-11-02/`, visszaállítás: `psql -f semak.sql`, majd `adatok.sql` a `--disable-triggers` miatt `session_replication_role=replica` mellett). A Dashboardon az Exposed schemas csak `public`, `graphql_public` lehet – egy nem létező séma a listán 503-at (`PGRST002`) ad a teljes REST API-ra. A régi `supabase/seed.sql` és a `szamlak` Storage bucket már nem használt.
- Flowable: `npm run flowable:logs`; BPMN kézi telepítése: `npm run flowable:deploy` (a rendeléskezelő induláskor magától telepíti); REST: `http://localhost:8080/flowable-rest/service` Basic auth-tal.
- Lint: `npx eslint app components lib legacy systems mcp scripts`
- **Portál: `npm run dev` (`http://localhost:3000`, hot reload)** – ez az egyetlen portál; a rendszerek konténerben futnak. A bekötött konténeres címeket (`http://billing:4103` …) natívan a gépi portokra fordítja (`lib/portal/kapcsolat-teszt.ts`, `elerhetoCim`). A `.env.stack`-ből csak a `PORTAL_INTEGRACIO_KEY`-t veszi át (`next.config.ts`). Opcionális, éles jellegű konténeres változat (bemutatóhoz): `npm run portal:kontener` (compose `portal` profil; a `stack:up` nem indítja; előtte állítsd le az `npm run dev`-et, egyszerre csak az egyik fusson).
- Füsttesztek (mind a konténeres rendszeren; közös segéd: `scripts/smoke/rendszerek.ts`): `01-alapok` (rendszerenkénti adatbázisok), `02-crm-katalogus`, `03-raktar` (~2 perc, DLQ), `04-ajanlat`, `05-szamlazas`, `06-flowable`, `07-rendelesek` (~3-4 perc), `08-fizetes` (stripe profil, ~1,5 perc), `09-support`, `11-order-to-cash` (stripe + SzámlaBridge, ~90 mp), `15-rendszerek` (egészség, függetlenség, kiesés-szimuláció; rendszereket állít le és indít vissza – ne fusson más teszttel párhuzamosan), `16-portal` (integrációk, kapcsolatteszt, irányítópult, szerepkörök, vezérlés; két ideiglenes Supabase-felhasználót hoz létre és töröl, a számlázót leállítja és visszaindítja – ne fusson mással párhuzamosan; futó `npm run dev` kell hozzá; a portál kódját átnézi, hogy nem olvas-e rendszerkulcsot). Kódváltozás után a rendszerképeket újra kell építeni (`npm run dc -- up -d --build <rendszer>`), különben a régi kód fut. Futtatás: `npx tsx scripts/smoke/<név>.ts`. A tesztek a kiszállított készletet visszavételezik (KORREKCIO). A bizonylatokat a tesztek maguk állítják ki (`scripts/smoke/bizonylatok.ts`: tesztvevő, számla, díjbekérő, fizetett, sztornó, lejárt – a lejártnál az éjszakai jelölést szimulálja); seedelt bizonylatra ne építs ellenőrzést (az éles rendszer üresen indul). A seedelt törzsadat (pl. a Duna Irodaház `VEVO-1001` a CRM-mel összekötve) még használatban van.
- **Ágens (17. fázis, natívan):** felületen: a portál **Asszisztens** oldala (`/asszisztens`, `npm run dev` + Ollama; jóváhagyási kártyák, a beszélgetések felhasználónként – `agens.futas.felhasznalo`); parancssorból: `npm run agens -- --szerep sales "kérés"` (kérés nélkül beszélgetős mód; `--folytat <thread_id>`, `--modell donki-gemma` (12b), `--auto-jovahagyas` (csak tesztekhez), `--reszletek` (lépések, tokenek)). Modellek (egyszer): `ollama create donki-gemma-e4b -f agens/Modelfile.e4b` (alapértelmezett) és `ollama create donki-gemma -f agens/Modelfile`. Saját adatbázis: `agens-db` (`127.0.0.1:54108`; `npm run dc -- exec agens-db psql -U postgres`; `agens.futas`, `agens.lepes`, a checkpointer a `langgraph` sémában). Nyomkövetés: `AGENS_NYOMKOVETES=1`. Mérés: `npx tsx scripts/agens-meres.ts [--modellek …] [--ismetles 2]`. Tesztek: `17-agens` (modell nélkül, ~5 mp; két ideiglenes Supabase-felhasználót hoz létre és töröl), `17-agens-elo` (helyi modellel, ~10 perc, sikerességi arány; `--modell`, `--ismetles`, `--kuszob`).
- **Értékelés (19–20. fázis):** mérés: `AGENS_FIGYELO=ki npx tsx scripts/ertekeles/futtat.ts [--valtozatok nyers,mcp] [--modellek donki-gemma-e4b,donki-gemma] [--ismetles 3] [--feladatok F01,F08] [--meres <címke>]` (folytatható: a meglévő futásokat kihagyja; kb. 2 óra a teljes készlet; a portál ne fusson közben). Riport: `npx tsx scripts/ertekeles/riport.ts [--meres <címke>] [--nyers <címke>] [--elozo <címke>] [--ki <md>] [--csv <csv>]` → alapból `riportok/01-meres/ertekeles-<címke>.md` és `riportok/01-meres/adatok/<címke>.csv` (a `--nyers` a nyers változatot egy másik mérésből veszi, az `--elozo` az előtte–utána összevetés; a 20. fázis riportja: `--meres 2026-11-07-javitott --nyers 2026-11-03 --elozo 2026-11-03`). Ellenőrző-javítás utáni újraértékelés a tárolt válaszokból: `npx tsx scripts/ertekeles/ujraertekel.ts [--valoban]`. Tábla: `ertekeles.futas` (agens-db). Feladatok: `scripts/ertekeles/feladatok.ts` (27 + 6 kontrollfeladat F25–F30 (`kontroll: true`, a 20. fázisban); előkészítés, ellenőrző, ideális megoldás, takarítás); a nyers ágens: `agens/nyers/eszkozok.ts` (csak a mérőfuttatóból, a legacy kulcsokkal). Teszt: `19-ertekeles` (modell nélkül, ~7 perc; az ellenőrzők próbája ideális és rossz megoldással; Számlázz.hu- és Stripe-tesztbizonylatokat állít ki). Az F24 a számlázó konténerét leállítja és visszaindítja. Riportok: `riportok/` (01-meres, 02-szakirodalom, 03-emberi-tenyezo, 04-penzugy, 05-osszehasonlitasok; index: `riportok/README.md`). További mérések (`scripts/riportok/`): emberi idő `npx tsx scripts/riportok/emberi-klm.ts`, majd `emberi-megtakaritas.ts`; pénzügy `npx tsx scripts/riportok/penzugy.ts` (a `riportok/04-penzugy/feltevesek.json` alapján újragenerálja a `penzugyi-elemzes.md`, `feltevesek.md` és `adatok/*.csv` fájlokat, adatbázis nélkül); tokenomika `npx tsx scripts/riportok/tokenomics.ts [--alap <címke>] [--opt <címke,…>]` (ciklusonkénti token, idő, költség, változatok összevetése; kimenet `riportok/05-osszehasonlitasok/adatok/tokenomics-*`) és `tokenomics-bontas.ts` (a szakágens-hívás bemenetének bontása az Ollama számlálásával); a kísérleti bemenet-csökkentés `AGENS_TOKEN_OPT=sema,sema-mind,elozmeny` (`agens/kozos/tokenopt.ts`, alapból kikapcsolva, csak a parancssori futtatás környezetéből olvassa, a mérés szerint kikapcsolva kell hagyni); 2. kör (Ö2, Ö3): `futtat.ts --feladatok B1,B2,B3,K1,K2,K3 --meres <címke>` (a `kulon` feladatok az alapkészletben nem futnak), terhelés `npx tsx scripts/riportok/terheles-meres.ts` (Ö4, kb. 15 perc), adatból `npx tsx scripts/riportok/osszevetesek-adatbol.ts` (Ö6, Ö7, Ö8, Ö9, Ö11, Ö12); a változástűrés részmérése `valtozas-meres.ts --csak V1:S1:mcp --utotag -javitott --build`; háttérfigyelő `caffeinate -dims npx tsx scripts/riportok/figyelo-meres.ts [--csak-j9]` (kb. 50 perc, a portál ne fusson, a Mac ne aludjon el); változástűrés `VALTOZAS_JELZO=$PWD/scripts/riportok/valtozas/aktiv NODE_OPTIONS="--require $PWD/scripts/riportok/valtozas/mutacio.cjs" AGENS_FIGYELO=ki npx tsx scripts/riportok/valtozas-meres.ts` (kb. 25 perc, közben ideiglenesen módosítja az `mcp/servers/*` és `legacy-docs/*` fájlokat, ezeket ne szerkeszd; a végén visszaállít és újraépít); adatkimenet: `HALOZAT_NAPLO=<fájl> NODE_OPTIONS="--require $PWD/scripts/riportok/halozat-naplo.cjs"` a Node-folyamatokra, a konténereket a Docker-VM `/proc/net/nf_conntrack` táblája mutatja. Ha a számlázó `E999`-et ad: a Számlázz.hu tesztfiók törölt bizonylatainak sorszámát adta újra – a számlázó ezt 2026-11-07 óta magától kezeli (a régi saját bizonylat `HIANYZIK` lesz).
- **Háttérfigyelő (18. fázis):** az `npm run dev`-vel indul (`instrumentation.ts` → `agens/figyelo/figyelo.ts`); a Rendszerek oldalon látszik és kapcsolható, `AGENS_FIGYELO=ki`-vel nem indul. Tesztek: `18-figyelo` (modell nélkül, ~1 perc; saját készlethiányos rendelés, ideiglenes készletkorrekció visszatöltéssel, szintetikus fizetési/szállítási esemény a sorokban), `18-figyelo-elo` (helyi modellel, ~1 perc, futhat a portál mellett).
